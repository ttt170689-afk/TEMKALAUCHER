# ЛС и игровая активность · 1.9.0 / Android 0.4.0

## Подключить к существующему серверу

Выполнить **online-1.9.0.sql** в SQL Editor своего существующего Supabase-проекта. Последняя строка результата: `TEMKA_CHAT_ACTIVITY_READY`. Файл включает повторяемые миграции friend-notifications, player-profiles, chat-activity. Базовая схема supabase.sql и beta-access.sql должны уже существовать — они ранее настраивались владельцем. Не создавать новый проект, не сбрасывать аккаунты и не перенастраивать SMTP.

Это добавление таблиц/RPC, а не перенос или очистка данных. Фото/роли/друзья/бета-допуски сохраняются. Перед изменением реального сервера рекомендуется обычная резервная копия. Файл можно выполнить повторно. В приложениях уже указан прежний публичный адрес/ключ проекта. Секретные ключи в APK/ZIP не нужны. Отдельный WebSocket-сервер, включение Realtime publication и домашний Xeon для этого обновления не требуются.

Тестовые SQL-файлы `test-*.py` НЕ запускать в Supabase. Они создают отдельные имитированные auth/storage схемы и предназначены только для пустой одноразовой локальной БД.

## Личные сообщения

Подтверждённая почта и онлайн-профиль обязательны. Отправка разрешена только при принятой дружбе; сервер проверяет обе стороны при каждой новой записи. Кнопка «Написать» есть у друга и в его открытой карточке. В шапке — конверт с непрочитанными. Письма/OTP автоматически из-за открытия чата не отправляются.

- До 2000 символов, 20 новых сообщений/минуту на отправителя, сериализация конкурентных отправок.
- UUID-повтор отправки одного текста не создаёт дубль, даже если первый ответ потерян. Текст очищается только после подтверждения сервера. Закрытие диалога/приложения не обещает сохранение неотправленного черновика.
- Загрузка по 50 сообщений, кнопка более ранних. Для стабильной пагинации используется время + UUID.
- Удаление из друзей запрещает дальнейшую отправку, но не стирает старую переписку.
- Счётчики синхронизируются между устройствами. Открытый диалог отмечает загруженные входящие прочитанными; квитанций «прочитано» у отправителя в UI нет.
- Нет файлов, звонков, фоновой доставки push и удаления/редактирования сообщений.
- **Не E2E:** передача через HTTPS, доступ к RPC ограничен участниками, но администратор базы может читать сообщения. Не пересылайте пароли, коды входа и другие секреты.

Прямой доступ anon/authenticated к таблицам переписки отозван, включён RLS. Запись и чтение — только через функции с фиксированным search_path и auth.uid(). Посторонний пользователь не может прочитать чужую пару или отметить чужое сообщение. Срок автоматического удаления переписки не задан; следите за объёмом бесплатной БД. Для небольшой группы отдельная платная служба не требуется, но безлимитное хранение не обещается.

## Что означает «Играет сейчас»

Это **активная сессия, сообщённая лаунчером**, не доказательство, что человек нажимает кнопки, и не защита от модифицированного клиента. Она не меняет доверенные `player_game_stats` — часы, уровни, достижения и XP.

- Нативный адаптер сообщает успешную загрузку конкретной отслеживаемой игры, её ID и уникальный ID запуска.
- Перед heartbeat координатор проверяет, что тот же нативный запуск ещё существует. Heartbeat — каждые 25 секунд.
- Закрытие игры инициирует stop. Сервер также снимает активность без cron, если heartbeat старше 90 секунд; карточки опрашиваются раз в 30 секунд. Обычно после обрыва статус исчезает в пределах 90–120 секунд с последнего heartbeat.
- Завершённая/просроченная сессия не оживает от позднего heartbeat. Новый запуск на другом устройстве завершает предыдущую активную сессию аккаунта.
- При недоступном сервере показывается неизвестный/недоступный статус, а не выдуманная игра.
- Последние 20 сессий доступны в профиле всем подтверждённым вошедшим игрокам, как и остальная публичная карточка. Email и токены не выдаются.

## В этой версии игры всё ещё «Скоро»

В серверном `activity_catalog` обе игры **disabled**, нативные allowlist также не содержат подключённых игровых URL, кнопки библиотеки неактивны. Обычный запуск этого APK/ПК-лаунчера не создаёт игровых записей. Существующий внешний браузерный URL не включается автоматически. Посещение сайта/браузера/панели beta не учитывается.

Для будущего готового браузерного билда разработчик должен одновременно подключить проверенный HTTPS-адрес в нативном allowlist, доступный нативный путь запуска и серверный каталог, проверить реальный цикл игры и бета-авторизацию. Простое изменение SQL-флага не разблокирует кнопку и не превращает внешнюю ссылку в отслеживаемую игру.

ПК: отдельное изолированное Electron-окно без Node, preload и доступа к токенам приложения; отслеживание загрузки/закрытия/падения. Android: отдельный WebView поверх приложения, без Capacitor JS bridge, file/content access и mixed content; аппаратный Back/кнопка закрытия завершают игру. Уход Android-приложения в фон также закрывает такой сеанс — скрытое время не записывается. Ошибки загрузки/SSL/HTTP и падение WebView не создают успешный запуск. URL из renderer произвольно не принимаются.

Никакого отслеживания стороннего APK, внешнего Chrome или игры, открытой отдельно, здесь нет. iOS-проект содержит общий интерфейс ЛС/истории, но нативный tracked-game адаптер iOS не реализован; не обещать на iPhone отслеживание внешних приложений. Готового IPA нет.

Бета-допуск проверяется сервером для начала/поддержания сессии, но сам по себе **не защищает распространение игры**. Готовая игра должна самостоятельно проверять подтверждённую учётную запись и актуальный допуск на своём backend. Сейчас распространять/запускать бета-игру из этой версии нельзя.

## Реальная проверка с братом

1. Применить SQL; установить обновление ПК через Publisher и APK на Android.
2. На телефоне войти в нужный онлайн-аккаунт по почте. Для разговора нужны два разных аккаунта, а не два устройства одного отправителя.
3. Принять дружбу, отправить текст ПК → Android и обратно. Закрыть диалог, проверить непрочитанные, открыть снова. Перезапустить приложение — история должна сохраниться.
4. Отключить сеть: ошибка не должна выглядеть успешной отправкой, черновик в открытом диалоге не очищается. Повторить после подключения.
5. Проверить фото, профиль, библиотеку и «⋯ → Свойства → Бета-тест». «Скоро» должно оставаться неактивным, история запусков — пустой до реального подключения игры.

Производственный сервер из чата не изменялся. Браузерные тесты используют имитацию backend; это не подмена заключительного теста на физических устройствах.

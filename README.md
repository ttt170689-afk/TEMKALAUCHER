# TemkaLauncher 1.5.6 · Альфа

## Что изменилось

- XP больше не начисляется: регистрация, ежедневный вход, переходы, вишлист и открытие веб-проекта не дают опыт. Уровни, прогресс, награды и связанные с ними блокировки убраны из интерфейса. Историческое `temka-progress-v1` не перезаписывается.
- Вишлист: одно нажатие → «Добавлено в вишлист». Без email, очереди и обещаний отправить письмо. Список общий для локальных профилей этого устройства, не отправляется автору и не синхронизируется с сайтом.
- При обновлении старые записи вишлиста переносятся в `temka-wishlist-v2` без email; старый ключ удаляется после успешного сохранения. Запись «all» превращается в две игры. Профиль, его почта, аватар и история отдельно сохраняются.
- «Обзор…» вызывает `dialog.showOpenDialog` Electron. Разрешены папки, проверяется доступ на запись; отмена сохраняет прежний путь. Повторные запросы используют один диалог. Браузерная версия честно отключает кнопку.
- Игры пока не устанавливаются. Выбор папки — настройка для будущих установок, а не начало загрузки.
- Сохранены новости, подпись разработчика, аватары, ники до 25 символов и клиент онлайн-друзей.

## Выпустить через программу Publisher

1. Закрой старый Temka Publisher и установи **TemkaPublisher-Setup-1.0.6.exe** из комплекта. Это маленький установщик Publisher, не большой EXE лаунчера.
2. Открой Publisher 1.0.6, выбери `TemkaLauncher-1.5.6-sources.zip`.
3. Укажи **1.5.6**, если номер ещё свободен, иначе следующий предложенный. Не удаляй и не перезаписывай опубликованные 1.5.3 и 1.5.5. Отдельно выпускать подготовленную 1.5.4 не обязательно.
4. Проверь репозиторий **ttt170689-afk/TEMKALAUCHER**, подтверди публикацию.
5. Дождись успешной сборки обеих платформ и проверки файлов релиза. При ошибке открой ссылку Actions, а не запускай параллельно другую публикацию с тем же номером.

**Почему нужен Publisher 1.0.6?** Он содержит новый native-updater: проверку GitHub API, согласование манифеста и пакета, закрепление загрузки за конкретным релизом. Старые Publisher заменяют native-файлы. Теперь исходники специально требуют `electron/native-contract.json`: старый шаблон вызовет ошибку сборки, а не незаметную потерю исправления.

## Главное исправление обновлений

- Свежий запрос публичного GitHub API и маленького манифеста конкретного релиза. Проверка версии, имени файла, размера и SHA-512; затем сверка с ответом electron-updater.
- При новой версии движок использует URL конкретного тега, а не полагается только на определение latest через feed.
- Сеть, HTTP 403/429, неверный JSON, отсутствующий установщик и несовпадающие версии — ошибка, а не «обновлений нет».
- Видимая панель с установленной/опубликованной версией и временем успешной проверки. Кнопка ждёт завершения запроса. Нет фиктивного уведомления по таймеру.
- Резервная кнопка открывает официальный список релизов. Автоматического обхода TLS или выдачи секретного токена нет.

**Если старая 1.5.3 не увидит новый выпуск:** после успешной публикации 1.5.6 открой https://github.com/ttt170689-afk/TEMKALAUCHER/releases/latest, проверь тег 1.5.6, скачай Windows Setup и установи поверх в ту же папку. Полностью закрой старый лаунчер, включая трей. Не удаляй AppData/локальные данные. Запусти новый ярлык и проверь номер в интерфейсе. Исправление внутри 1.5.6 не может автоматически переписать код уже работающей 1.5.3 без установки обновления.

Номер пакета остаётся обычным SemVer `1.5.6`; «Альфа» — стадия готовности продукта в интерфейсе. Workflow публикует обычный релиз, чтобы его видел существующий updater; это не GitHub prerelease и не отдельный alpha-канал обновлений.

## Друзья

Сейчас сервер в комплекте **не подключён**. У двух пользователей должна быть одна общая база и одинаковая публичная конфигурация. Локальные аккаунты на разных ПК не видят друг друга автоматически.

Читай `backend/БЕСПЛАТНЫЙ-СЕРВЕР-И-XEON.md`, затем `backend/ПОДКЛЮЧИТЬ-ДРУЗЕЙ.md`. SQL для нового проекта — `backend/supabase.sql`. Вариант для начала: Supabase Cloud Free. Свой Xeon возможен, но поддержка произвольного self-hosted URL в текущем клиенте ещё не включена; простая подстановка домашнего IP не заработает.

## Разработка и проверки

Node 22.12+:

```sh
npm ci
npm test
npm run build
npm run test:smoke
node scripts/smoke-news.cjs
node scripts/smoke-alpha.cjs
```

В Linux UI-тесты запускать через `xvfb-run -a`. В рабочем приложении sandbox включён; `--no-sandbox` используется только в изолированном Linux CI-тесте.

Windows/Linux установщики собирает GitHub. Здесь большой Windows EXE лаунчера не создавался и не скачивался. Linux-лаунчер не означает поддержку Linux самими играми. На реальном Windows нужно проверить внешний вид системного диалога и выбранную папку после установки.

Готовая сборка и сайт **не опубликованы из этой сессии**. Живой сайт в чате — предпросмотр, не постоянный хостинг.

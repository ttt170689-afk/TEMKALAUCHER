# TemkaLauncher PC1.9.10 · Alpha

## Скачать/распаковать/запустить игру из лаунчера

После ключа: Библиотека → Fantazia → «Бета · установить / играть» → предупреждение/пустая галочка → **Скачать и установить**. Native Electron скачивает полный portable-пакет, проверяет SHA256 внешнего ZIP и вложенного игрового ZIP, безопасно распаковывает все DLL/resources/locales. Браузер за файлом не открывается. Нужно1ГБ свободного места. Корень по умолчанию **Документы/TemkaGames**; для другого выбери Настройки → Обзор до установки. Путь показывается в диалоге.

После проверки появляется **Играть**: отдельный клик запускает `Fantazia RP 3D.exe`, cwd=папка игры, shell:false/без аргументов/PowerShell. Перед запуском заново проверяются доступ аккаунта и все хэши/состав/отсутствие ссылок. Подмена, лишние DLL, отсутствующие файлы блокируют запуск. Существующую неизвестную папку не затираем, данные не удаляем; смена папки требует закрыть игру. Закрытие лаунчера не убивает процесс игры. Без Windows поддерживаемого клиента нет: Linux-лаунчер сохраняется, но эта игра на Linux не запускается.

Пакет фиксирован: существующий DriveID1hH7PxjQEu4bSDQDdi6r0gVEpDZ0glFZL, внешний ZIP153178080bytes/SHA256`111591e160f6005e3aa3cb49e43ddfdcbfaaec1b1be7168e108f4c920891eac5`. Внутренний`Fantazia-RP-Portable-1.0.1-win-x64.zip`153173775bytes/SHA256`b769cd37505bc37403040bb65887d46dac9217eec1093c23445b8e4494fe9abb`. Полная распаковка375МБ/75entries. Старый101МБ NSIS-установщик не используется. Источник unsigned/test, проверка SHA не является антивирусным аудитом.

Здесь по HTTP-range проверены каталоги, исходный SHA-файл, compiled app.asar/version1.0.1 и MZ/PE x64 заголовок EXE. Полный Windows-файл не скачивался/не запускался; runtime-проверку полного хэша выполняет лаунчер при скачивании игроком. До класса нужен реальный запуск на Windows10/11x64.

## Обновление через привычный Publisher

Этот полный ZIP → **Publisher1.1.2 → Лаунчер**. Новый Publisher не нужен: native-bundle и build-tools восстанавливают новый bridge/ZIP-manager поверх старого встроенного шаблона. Не импортировать только dist. Не удалять native-bundle/build-tools и не обходить checksum failures. После импорта обязательны restore-native, typecheck/tests/build; Windows EXE выпускается твоим обычным GitHub workflow, не этим Linux sandbox. Published tags не перезаписывать. Source version1.9.10, APP_VERSION следует версии, выбранной Publisher.

Локально Node22.12+, `npm ci`, `npm run build`, затем `npm test`. Vite автоматически вызывает restoreNative из vite.config.js до сборки и запускает post-restore TypeScript/все226тестов. Прямой вызов модуля `node build-tools/restore-native.mjs` не является CLI-командой восстановления. Полный Windows-лаунчер здесь не собирался/не скачивался, как было запрошено. Текущий sourceZIP проверяется настоящим импортом ProjectFiles/ApplySupport1.1.2 и post-restore tests.

## Ключи и основной сервер

Закрытая Fantazia Beta0.1 — НЕ закрытый Dev лаунчера. Доступ проверяет основной сервер по подтверждённому аккаунту: `beta_status(fantazia)` и `beta_redeem`. Никаких локальных `approved=true`, готовых ключей в коде или обхода авторизацией «локальный режим». Перед действиями проверка повторяется и в native-коде.

Автор: **Publisher1.1.2 → Beta Test → Fantazia RP → Режим кода «Доступ сразу» → Игроков → Создать ключ**. Ключ показывается один раз. «Моё одобрение каждой заявки» оставит запрос pending до решения автора. Тестер: **⋯ → Свойства → Бета-тест → Бета-код**, затем открыть установку/игру. Отзыв доступа тестера блокирует последующие действия лаунчера; отключение самого ключа не отзывает уже одобренные аккаунты. Новых реальных ключей при подготовке не создавали.

Пользователь явно выбрал **проверку ТОЛЬКО в лаунчере**. Пересланный отдельно EXE/APK, извлечённый встроенный APK и прямой игровой сайт этим не блокируются. Игровой сервер/login не переделывались; это не DRM/SSO и не защита ранее опубликованных файлов.

## Игра и ограничения

Игра обозначена Beta0.1; версии оболочек Android1.0.2-test/Windows1.0.1 — отдельные. Основной сайт **https://fantazia-rp-3d1.onrender.com/**. Нужны интернет и сервер; холодный Render старт может занять до2минут. Windows-клиент может попросить адрес при первом подключении: в лаунчере есть кнопка копирования. Это онлайн-клиенты, не весь офлайн-Godot/сервер внутри пакета. Общего игрового SSO нет. Скорость/FPS/голос/ресурсыv45/нагрузка класса не подтверждены health-запросом.

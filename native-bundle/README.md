# TemkaLauncher1.8.0 · Alpha · ПК

## Уточнение перед публикацией1.8.0

По просьбе владельца основная кнопка страницы игры в библиотеке — **«Скоро»**, неактивна и не открывает браузер. Убраны подписи о доступной браузерной версии из библиотеки. Другие разделы и данные игр этим точечным изменением не менялись.1.8.0 ещё не опубликована на момент проверки, новый номер не создавался.

## Профили и библиотека

- Новая библиотека: компактный список игр, большая страница выбранного мира, обзор, вкладки разработки/дополнений/прогресса, поиск и фильтр вишлиста. Свой интерфейс Temka, не копия оформления/ассетов Steam. Иллюстрации помечены как иллюстрации, не игровые скриншоты.
- Профили игроков открываются по аватарке/нику в поиске, друзьях и уведомлениях. Фото, публичное имя, @юзернейм, описание, серверная роль и настоящая статистика по каждой игре. Почта скрыта. Доступ — вошедшим с подтверждённой почтой, по выбору владельца.
- Поиск по части ника от2 символов, без учёта регистра, до20 результатов; exact match первым. Защита от устаревших запросов, ошибок и повторных приглашений сохранена.
- Одна аватарка: новое выбранное фото при готовом онлайн-профиле сразу загружается. Отдельной кнопки публикации нет; старые локальные фото сами не отправляются. Публичный файл доступен по ссылке; предупреждение показано до выбора.
- Свои встроенные аватары тоже можно выбрать для онлайн-карточки. Описание/имя сохраняются отдельно от локального имени устройства.
- Уровни, часы и достижения — по конкретной игре. До интеграции игрового backend отображается «Нет данных», не выдуманные числа. Время лаунчера/браузерной вкладки не считается игровым.

## Подключение обновления

Сначала выполнить **backend/player-profiles.sql** в SQL Editor владельца (ожидается TEMKA_PLAYER_PROFILES_READY). Это аддитивная миграция, не исходный setup. Данные и права не пересоздаются. Затем импортировать этот ZIP через имеющийся Publisher с новым свободным номером1.8.0. Подробно: **ЗАПУСК-1.8.0.md**.

Из чата production SQL/публикация не выполнялись. Mobile0.3.0 не менялся. Сервер SMTP и creator_admin уже настроены и подтверждены пользователем — не начинать настройку заново.

**БЕТА-И-DISCORD.md** объясняет выдачу кодов, отличие допуска от защищённого запуска, структуру Discord/права каналов. Discord-сервер ещё не создан; его приглашение не придумано. В лаунчере нет SQL/tutorial-кнопок.

## Native / Publisher

Publisher1.0.9 подставляет старые electron/tests/smoke. Vite config JS перед сборкой проверяет и восстанавливает **25 файлов / protocol3** из native-bundle, повторяет TypeScript и обязательные runtime tests. Защищены clipboard, smoke, CI/CRLF и player-card contracts. SHA-256 нормализует только переводы строк. Не обходить CI, не принуждать старый vite.config.ts. Builder включает electron/**/*.

Node22.12+: npm ci; npm test; npm run build; npm run test:smoke (Linux: xvfb-run -a npm run test:smoke). Реальные проверки/границы в TEST-REPORT.md. scripts/smoke-major.cjs — две mocked личности, desktop1.8 + неизменённые web-assets mobile0.3.0; MAJOR_TEST_URL указывает на локальный сервер с /desktop/ и /mobile/. Production не использовать как тестовый backend. backend/test-*.py — только одноразовая БД, не Supabase.

Windows Actions/installer из чата не запускались. Не выдавать Linux/Xvfb + CRLF за полноценный Windows-прогон. Новые CI gates остаются обязательными до упаковки/публикации.

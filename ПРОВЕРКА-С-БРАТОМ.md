# Проверка с братом: два настоящих аккаунта

Это ручной чек-лист после публикации/установки 1.8.0. В чате эти действия на рабочем сервере не выполнялись.

## Подготовка
- На обоих ПК — новая сборка. Мобильный проект тоже обновлён, но APK/IPA этого выпуска нужно собрать отдельно.
- У каждого своя почта: один общий онлайн-аккаунт на двоих не проверит дружбу.
- Базовая схема уже применена владельцем. Если ранее не выполняли обновление уведомлений — выполнить backend/friend-notifications.sql. Результат TEMKA_NOTIFICATIONS_READY. Данные не удаляются; не пересоздавать проект.
- Оба шаблона письма Confirm sign up и Magic link or OTP содержат {{ .Token }}. SMTP уже настроен владельцем. Новый код запрашивать не чаще раза в 60 секунд, использовать самое новое письмо.

## Друзья
1. Профиль → подтвердить свою почту → сохранить **разные онлайн-юзернеймы**. Не путать локальное имя с @юзернеймом. Для temka_play_official сначала нужна роль создателя; тестовому игроку — обычный свободный ник.
2. Каждый проверяет имя + @юзернейм в шапке/профиле. Перезапуск не должен превращать сохранённый онлайн-ник в локальный.
3. Ты: Друзья → Добавить друга → полный @юзернейм брата → Найти → Отправить заявку.
4. У тебя заявка в «Исходящих», в колокольчике не считается. У брата — входящая, виден твой @юзернейм. При видимом окне подождать до 30 секунд или нажать обновление.
5. Брат принимает. Обновить оба списка: оба видят друг друга во «Всех друзьях».
6. Проверить отмену удаления: нажать «Удалить из друзей», затем «Отмена» — связь остаётся. Подтверждённое удаление действительно убирает её с обоих аккаунтов после обновления.
7. Повторить приглашение: брат отклоняет. Ещё раз пригласить и отменить самому. Входящие/исходящие не должны оставаться после обновления.
8. Попробовать найти себя, несуществующий ник, уже добавленного игрока. Самоприглашение и повторная заявка не должны появиться.
9. Отключить интернет: ошибка, а не сообщение об успешной отправке. Включить и повторить обновление.
10. Выйти из онлайн-профиля: имя на устройстве остаётся, чужие друзья/уведомления и онлайн-юзернейм не показываются.

## Бета (когда назначена роль владельца)
1. Проверенный UUID своего подтверждённого аккаунта взять в Authentication → Users. Только владелец проекта назначает creator_admin по инструкции backend/БЕТА-ТЕСТЫ.md. Не назначать роль по локальному нику или UUID брата.
2. Владелец: Библиотека → Fantazia RP → ⋯ → Свойства → Управление. Создать отдельный тестовый код в режиме «Моё одобрение каждой заявки», на 1 игрока.
3. Брат: Свойства → Бета-тест → код → ожидание одобрения. У обычного игрока вкладки управления быть не должно.
4. Владелец одобряет заявку; брат проверяет статус и видит одобрение. Затем протестировать отзыв.
5. Неверный/истёкший/отозванный код не должен давать доступ. Не перебирать: сервер ограничивает 5 попытками за 10 минут.

**Одобрение пока не скачивает и не запускает Fantazia RP.** Для закрытого тестирования самой игры отдельно нужны сборка/хостинг и проверка доступа в игре или на сервере выдачи. Публичная ссылка сама по себе не защищена кодом лаунчера.

При проблеме: версия лаунчера, шаг, точный текст ошибки, скрин без кодов/паролей/токенов. Не пересоздавать пользователей и не стирать базу ради диагностики.

# Исправление 1.5.2 — компактное меню и smoke-тест

- До исправления воспроизведён точно такой же тайм-аут поиска «Профиль» при viewport 980×700. При этом регистрация успешно завершалась; доступных кнопок с именем «Профиль» было 0, хотя кнопка находилась в DOM.
- Причина: текст `hidden lg:block` скрывал единственный источник доступного имени. Добавлены `aria-label`, `title`, `aria-current` в Sidebar.
- После исправления пройдены 14 unit-тестов, TypeScript, Vite production build и Electron smoke при 980×700 и 1280×800. Тест не отключён и не помечен continue-on-error.
- При будущей ошибке сохраняются снимок экрана, сведения о стадии/кнопках и Playwright trace. Workflow прикладывает их к неудачному запуску.
- Publisher 1.0.2 содержит новый smoke-тест и исправляет доступные имена при импорте стандартного старого Sidebar.
- Проверки выполнены локально в Linux/Xvfb. Повторный запуск в Windows GitHub Actions ещё должен выполнить пользователь. Новый Windows EXE 1.5.2 в этой сессии локально не собирался.

# Проверка TemkaLauncher 1.5.0

Дата: 2026-10-11. Среда: Linux x64, Node.js 22.23.3, Electron 44.7.0, electron-builder 26.15.3. Windows-установщик собран через NSIS/Wine; интерфейс запускался в Linux Electron через Xvfb.

## Выполнено успешно

- `npm run typecheck`: TypeScript без ошибок.
- `npm run build`: production-сборка Vite завершена.
- `npm test`: **11 из 11** unit-тестов пройдено. Покрыты новая/равная/старая/некорректная версия, ошибка сети и повторная попытка, одновременные проверки и загрузки, установка без предварительной проверки, ожидание проверки, ошибка загрузки и запрет установки незагруженного файла, повторная установка уже скачанного обновления, режим разработки.
- `xvfb-run -a npm run test:smoke`: запущено настоящее окно Electron; проверены preload, версия 1.5.0, отсутствие `window.require`, локальная регистрация, переход в настройки, показ ошибки проверки, мост события трея, сохранение сессии после перезагрузки. Не зарегистрировано исключений JavaScript в renderer.
- `electron-builder --config electron-builder.cjs --win nsis --x64 --publish never`: успешно получены установщик EXE, `.exe.blockmap`, `latest.yml`.
- `npm run verify-release`: сверены PE-заголовок установщика, версия, размер, SHA-512, наличие blockmap и встроенный адрес GitHub Releases.

## Что НЕ проверено / НЕ сделано

- Установка, запуск, выход в трей и удаление на реальной Windows 10/11.
- Полный сетевой цикл самообновления двух настоящих Windows-сборок через GitHub Releases. Unit-тесты используют подставной транспорт и не заменяют такой тест.
- Выполнение GitHub Actions в удалённом репозитории: workflow только подготовлен.
- PowerShell-скрипт публикации не запускался под пользовательской учётной записью GitHub.
- Исходники не отправлены в удалённый репозиторий, релизы не опубликованы.
- Подпись EXE сертификатом издателя: сертификат не предоставлен.

При проверке публичного репозитория `ttt170689-afk/TEMKALAUCHER` он доступен, а запрос последнего опубликованного релиза вернул 404. Это состояние на момент работы, не гарантия дальнейшего состояния репозитория.

## Приёмочный тест на Windows после публикации

1. Установить 1.5.0 из приложенного EXE; открыть интерфейс, создать тестовый локальный профиль.
2. Убедиться, что версия указана 1.5.0, настройки сохраняются после выхода и запуска.
3. Опубликовать 1.5.1 через workflow с EXE, `latest.yml` и `.blockmap`.
4. В установленной 1.5.0 нажать «Проверить обновления» либо дождаться фоновой проверки.
5. Проверить прогресс загрузки. Нажать «Перезапустить»; убедиться, что появилась версия 1.5.1, профиль и настройки сохранены.
6. Отдельно проверить установку при полном выходе из трея.
7. Отключить сеть: приложение должно открываться, а ручная проверка сообщать об ошибке, а не об отсутствии обновлений.
8. Проверить настройки отключения автопроверки/автозагрузки, повторный запуск и одиночный экземпляр.
9. Проверить удаление через «Установленные приложения». Пользовательские данные намеренно не удаляются автоматически.

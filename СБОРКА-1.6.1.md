# Исправление повторной ошибки сборки

В 1.6.1 не требуется ещё одна переустановка Publisher. Отправляй этот полный ZIP через имеющийся **1.0.6 или 1.0.7**, с новым свободным номером 1.6.1. Не нажимай Re-run на прежнем неудачном запуске.

Старый Publisher может вставить свой шаблон при отправке — это теперь учтено. Перед упаковкой приложение восстанавливает нужные файлы из `native-bundle`, проверяет их SHA-256, повторяет TypeScript и тесты native-обновления. Это полноценный исправленный код без GitHub API, не пустой JSON ради обхода ошибки.

В архиве важны `vite.config.js`, `build-tools/` и `native-bundle/`. Не удаляй их. Обычная команда workflow `npm run build` выбирает новый конфиг автоматически. Сообщения `[Temka runtime]` появятся в журнале.

Источник проверки в установленной новой версии: «GitHub Releases · напрямую, без API». Сама публикация не меняет старую установленную программу: если она не обновится автоматически, скачай новый Setup после публикации и установи поверх, предварительно закрыв лаунчер полностью. Данные профиля не удаляй.

Теги неудачных попыток не перезаписывай. 1.6.1 в этом чате только подготовлена, не опубликована от твоего имени.

# Проверки 1.5.9 — 2026-10-12

## Повторён именно проблемный путь

- Использована настоящая логика ExtractProject/ApplySupport из Publisher 1.0.6 и 1.0.7 через их PublisherTests.exe --prepare. Это не ручная имитация native-шаблона.
- После импорта через 1.0.6 подтверждено отсутствие electron/release-feed-contract.json и присутствие сохранённого native-bundle. Затем обычная команда npm run build успешно прошла первичный TypeScript, восстановление файлов, повторную типизацию, runtime-тесты и Vite.
- 1.0.6: восстановлено 6/15 файлов; 1.0.7: 4/15. После обоих импортов итоговые native-файлы, updater UI, тесты и dist/index.html побайтно совпали с исходной исправленной сборкой.
- Восстановление включается штатным выбором vite.config.js; workflow, заменённый Publisher, по-прежнему вызывает npm run build.

## Автоматические проверки

- Полный исходный проект: **48/48** unit-тестов.
- До сборки обоих импортированных проектов: **36/36** тестов, оставленных/добавленных шаблоном Publisher.
- Во время сборки после восстановления: **36/36** проверок runtime/комплекта в каждом проекте.
- 6 новых тестов комплекта: возврат реального API-free кода и отсутствующего JSON, повторный запуск без изменений, повреждение/отсутствие файла с отказом до записи, Windows CRLF, неожиданный путь manifest, символьные ссылки (в том числе оборванные, source и destination). Проверка ссылок выполнялась на Linux; на Windows этот тест пропускается, сама защита остаётся.
- TypeScript + Vite: успешно в оригинале и после Publisher 1.0.6/1.0.7.
- После импорта через 1.0.6: реальный Electron smoke, **11** проверок UI обновлений, **23** новости/создатель/справка, **17** Alpha/вишлист/папки — успешно. IPC-ответы обновления и выбор в диалоге подменены в соответствующих UI-сценариях; интерфейс, preload и IPC настоящие.
- После импорта через 1.0.6 реальный Electron net.fetch получил опубликованный релиз 1.5.7 через прямой манифест и проверил файл HEAD-запросом. Реальный NsisUpdater увидел 1.5.7 для тестовой 1.5.3; downloadStarted=false. Это metadata-only тест Windows-движка под Linux, не установка на Windows.

## Границы проверки

Тесты выполнены в Linux sandbox, включая C# Publisher через Mono. Новая GitHub Actions-сборка на Windows/Linux из чата не запущена; итоговые инсталляторы 1.5.9 ещё не опубликованы. Большой Windows EXE не скачивался и не собирался. Финальную установку/автообновление на пользовательском Windows надо проверить после выпуска. Убрана зависимость от GitHub REST API, но блокировка всего GitHub/CDN всё ещё может помешать обновлению; такие ошибки не выдаются за «актуальную версию».

Публикация не исправляет уже установленный старый экземпляр сама по себе: если он не сможет обновиться, нужен новый Setup поверх существующей установки. Профили не удалять. Backend друзей/почта/игры не развёрнуты, сайт в этом ZIP не менялся.

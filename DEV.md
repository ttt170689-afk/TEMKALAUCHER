# Temka Dev — отдельная закрытая среда в обычном ПК-лаунчере 1.9.8

## Что изменилось

Пункт Dev в обычном меню — теперь только вход. Нажатие **«Войти в Dev»** открывает отдельный полноэкранный интерфейс со своей навигацией, оформлением и кнопкой **«Вернуться в обычный лаунчер»**. Обычные меню/поиск/кнопки за ним недоступны для мыши и клавиатуры (нативный modal top layer). Escape также возвращает в обычный режим.

Это среда для **новых функций TemkaLauncher**, не игровых серверов и не ранних версий Fantazia/TemkaWorld. Внутри: обзор, ранние функции и вспомогательный каталог только ПК-сборок лаунчера. Страница входа больше не заменяется каталогом скачиваний.

**Отдельных экспериментальных функций и ранней сборки пока нет.** Интерфейс прямо сообщает об этом. Переключение режима не меняет установленную версию и не загружает исполняемый код. Автоматического закрытого канала обновлений нет; обычный updater не изменён.

## Как пользоваться после публикации обновления

1. В обычном лаунчере войти в свой существующий подтверждённый основной аккаунт.
2. Открыть **Dev**.
3. Владельцу с уже распознанным доступом: **«Войти в Dev»**. Второй аккаунт, регистрация и новый код не нужны.
4. Брату без доступа: вставить одноразовое Dev-приглашение → **«Войти в Dev по приглашению»**. После активации откроется отдельная среда, но только после повторного подтверждения сервера.
5. В дальнейшем для того же аккаунта достаточно **«Войти в Dev»**. Код повторно не вводится.
6. Вверху среды — **«Вернуться в обычный лаунчер»**. Основной сеанс аккаунта сохраняется. При перезапуске приложения Dev автоматически не открывается.

Выдача/отзыв приглашения по-прежнему только **TemkaPublisher 1.1.2 → Beta Test → Dev · ПК**. В лаунчере нет админ-кнопок или клиентских issue/revoke функций. Приглашение одноразовое, срок 24 часа, один tester-слот. Игровые Beta Test-коды не подходят.

## Проверки доступа

- Новый серверный status при каждом входе, а не доверие значку owner на публичной странице.
- Повторная проверка каждые 20 секунд, при возвращении фокуса/сети и после скрытия окна. На время проверки закрытое содержимое не отображается.
- Клиентская проверка действует максимум 30 секунд; это не самостоятельное разрешение сервера. Скрытие/потеря сети сразу блокируют среду, возврат требует нового ответа.
- Отказ, таймаут, смена аккаунта, выход и поздний ответ старого запроса не сохраняют разрешённый доступ.
- Запросы каталога/скачивания проходят свежую проверку до и после операции. Сам шлюз также независимо проверяет MAIN bearer и серверное членство. После отзыва завершившийся поздно файл не передаётся на сохранение.
- Не сохраняется локальный флаг права/роли/открытого Dev. MAIN-сессия использует существующий механизм лаунчера.
- Ограничение двух аккаунтов обеспечивается существующей серверной схемой: уникальные slots owner/tester, не списком ников на клиенте. Локальная модификация UI не даёт серверных прав.
- Будущие секреты и привилегированные операции должны оставаться на сервере. Встроенный frontend сам по себе не является секретным кодом.

MAIN Auth, Dev Gateway/SQL/RLS, роли, ранее активированный доступ и приватный bucket не менялись. Если текущий лаунчер уже показывает «Dev-доступ: владелец», ради этого обновления **не переустанавливать SQL, не создавать новую схему и не регистрироваться заново**. Первоначальная настройка сервера описана отдельно в backend/dev; она не является шагом обновления 1.9.8.

## Публикация и ограничения проверки

Через существующий ZIP-поток TemkaPublisher импортировать **TemkaLauncher-1.9.8-sources.zip**, новая версия **1.9.8**. Старые опубликованные теги не перезаписывать; если номер уже появился к моменту публикации, выбрать следующий свободный. Дождаться обоих Windows/Linux gates. Подробности в PUBLISH-1.9.8.md.

В этой работе выполнены локальные unit/build/настоящие Electron проверки на синтетических серверных ответах. Реальный owner/tester вход, отзыв на живом сервере и физический Windows требуют пользовательской проверки после публикации. Никакие реальные приглашения/OTP не использовались, на живой сервер и GitHub ничего не публиковалось. Большой Windows-инсталлятор не создавался и не скачивался. Android/iOS не изменены.

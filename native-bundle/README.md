# TemkaLauncher 1.7.1 · Alpha

## Исправлена остановка сборки 1.7.0

В 1.7.0 кнопка локального имени стала «Сохранить имя», но CI smoke продолжал искать «Сохранить». Дополнительно Publisher 1.0.9 перезаписывает scripts/smoke-electron.cjs своим старым шаблоном. Поэтому недостаточно исправить только рабочий файл.

В 1.7.1 актуальный обязательный Electron smoke и его регрессии включены в native-bundle. Во время npm run build они восстанавливаются после Publisher; контроль SHA-256 и реальный smoke не отключены. Используются точные доступные имена поля/кнопки, проверяются все шесть разделов и обязательная загрузка аватара. Выполнены настоящий Electron smoke на Linux/Xvfb и полный локальный импорт через код Publisher → unit → build → native smoke. Установщик Windows из чата не собирался.

**Выбрать новый ZIP и новый свободный номер. Не Re-run старых исходников 1.7.0 и не перезаписывать старый тег.** Publisher обновлять для этого исправления не требуется.

## Большое обновление: друзья и понятный профиль

- Отдельный раздел **Друзья**: **Добавить друга → полный @юзернейм → Отправить заявку**. Имя игрока и уникальный онлайн-юзернейм — разные поля.
- Твой @юзернейм в шапке, боковом меню, профиле и карточке друзей; копирование для приглашений.
- Вкладки «Все друзья», «Входящие», «Исходящие», фильтр текущего списка, ручное обновление. Удаление принятой дружбы требует подтверждения.
- Колокольчик показывает только входящие pending, принимает/отклоняет и открывает общий раздел друзей.
- Одна проверка онлайн-аккаунта и один таймер для всех этих экранов. Обновление раз в 30 секунд в видимом окне и при возвращении в него; push при закрытом приложении нет.
- Профиль отвечает за имя, онлайн-вход, юзернейм и аватарку; список и поиск друзей из него перенесены, не продублированы.
- Убраны пустые пункты «Магазин»/«Моды», лишние подписи и устаревшие сообщения. Игры, дорожные карты, новости, настройки, вишлист, свойства и beta сохранены.

## Исправления

Ошибка списка не превращается в повторную регистрацию. Черновик юзернейма не сбивается опросом. Шаг ввода почтового кода и 60-секундная пауза переживают навигацию/перезапуск в пределах часа; код и пароль в этом черновике не сохраняются. Опоздавший результат поиска не подменяет новый запрос. Отправка заявки требует корректного ответа сервера; на недоступном списке нельзя создавать повторную заявку. Принятие/отклонение проверяют результат, устаревшее отклонение не удаляет принятую дружбу. Профиль не сообщает успех при ошибке записи в локальное хранилище. Права управления бета-тестом сбрасываются при смене/выходе онлайн-сессии. Смена раздела сбрасывает прокрутку.

## Выпуск через Publisher

1. **Publisher 1.0.9 → «Лаунчер · Windows / Linux»**.
2. Выбрать `TemkaLauncher-1.7.1-sources.zip` целиком, без распаковки.
3. Репозиторий: `ttt170689-afk/TEMKALAUCHER`; версия **1.7.1, только если свободна**, иначе следующий свободный номер. Старые теги и неудачные релизы не перезаписывать.
4. Дождаться завершения Publisher/GitHub Actions, затем обновить установленный лаунчер. Из чата этот выпуск не публиковался.

Если старая установленная версия не обновляется, после публикации скачать Setup из своего GitHub Releases, полностью закрыть лаунчер вместе с треем и установить поверх. Не удалять AppData и профили. Большой EXE в этом комплекте не создавался и не скачивался.

## Онлайн-настройки не нужно создавать заново

Публичная конфигурация Supabase уже в `src/config/online.public.json` (Project URL + publishable key). Пароля базы, SMTP-пароля, service_role/sb_secret здесь нет. Пара env `TEMKA_SUPABASE_URL`/`TEMKA_SUPABASE_ANON_KEY` имеет приоритет только целиком; не смешивать разные проекты. В Publisher публичный src-конфиг сохраняется.

Владелец уже создал Supabase, применил базовую схему, настроил SMTP/шаблоны и показал успешное подтверждение почты. **В этом обновлении не менялись его настройки сервера и не отправлялись настоящие письма.**

Новой миграции для 1.7.1 нет. Если **предыдущее** `Temka-Launcher-Notifications-Update.sql` ещё не выполнялось, нужно выполнить `backend/friend-notifications.sql` в своём SQL Editor (повторяемо, без удаления данных). Подтверждения применения этой миграции из чата пока нет. Она обеспечивает серверное требование подтверждённой почты, не только блокировку кнопок.

Для ника `temka_play_official` и управления бетой нужна роль `creator_admin`, назначенная владельцем по проверенному Auth UUID. Локальный ник не выдаёт прав; роль автоматически никому не назначается. Инструкции только в backend/, не в интерфейсе игроков. Не выдавать anon SELECT на закрытые таблицы.

## Закрытая бета

**Библиотека → ⋯ → Свойства → Бета-тест.** Код проверяет сервер; ручное одобрение/автоматический режим, просмотр статуса, отзыв и права владельца сохранены. После rejected/revoked нужен автор: новый код не обходит прежнее решение.

**Это реестр доступа, а не доставка игры.** Файлы Fantazia RP, загрузка/запуск бета-сборки и авторизация внутри браузерной игры ещё не подключены. Открытый адрес браузерной игры эта версия не защищает. Readiness автора: Fantazia RP **80%**, TemkaWorld **10%**. Alpha сохранена, XP не возвращён, вишлист без email.

Реальная проверка с братом — `ПРОВЕРКА-С-БРАТОМ.md`. Локальные тесты HTTP/Auth не заменяют два живых аккаунта.

## Native-код и разработка

Node 22.12+: `npm ci`, `npm test`, `npm run build`, `npm run test:smoke`. На Linux последний шаг выполнять через `xvfb-run -a npm run test:smoke`. Production-команда сборки — именно `npm run build`.

`native-bundle/` защищает актуальный desktop-runtime от подстановки старого шаблона Publisher. В `vite.config.js` восстанавливается только точный список 18 файлов, сверяется SHA-256 (LF/CRLF нормализуются), повторяются TypeScript/runtime-тесты, включая tests/ci-smoke.test.cjs. В защищённом наборе теперь есть scripts/smoke-electron.cjs. Protocol **3**, прямой GitHub Releases feed без обязательного GitHub REST API сохранены. Проверки не отключены, фальшивых манифестов нет. Не запускать с принудительным старым `--config vite.config.ts`.

После намеренной правки восстанавливаемого файла/README: `node build-tools/refresh-bundle.mjs`, затем повторить тесты и build. Manifest — контроль целостности, не цифровая подпись.

Новый браузерный прогон: `scripts/smoke-major.cjs`, требует локальные собранные `/desktop/` и `/mobile/` по MAJOR_TEST_URL. Все сторонние API перехватываются, OTP имитированы. Подробности и честные границы — TEST-REPORT.md. Старые alpha/beta smoke-скрипты — исторические сценарии с отдельными fixtures, не актуальный end-to-end тест нового UI.
